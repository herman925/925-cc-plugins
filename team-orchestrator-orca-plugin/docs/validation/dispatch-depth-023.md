# 0.1.23：本机团队派工深度准备

验证日期：2026-10-18。用户在 #130 的 Head → Lead → Worker 实测中收到原生 `nested_worker_depth_exceeded` 拒绝，授权插件在启动前自动确保本机所需深度至多提升到 2，并保留原有更高设置。

## 行为

- 按已保存名册的父子关系计算：根主管为 0，单主管带 Worker 需要 1，多主管三层团队需要 2；11／21 人均为 2。
- 在新鲜会话、模型能力、配置版本及保存的执行主机校验后，成员预留和任何 provider 创建前，通过原有 `settings:get`／`settings:set` 准备深度。
- 本机不足 2 时只写 `{nestedWorkerMaxDepth: 2}`，通过同一个真实面板主 frame 的事件及现有插件 consent／owner 检查，读回确认后继续。同步使用原生 `settings:changed` 通知原窗口，因为原生 setter 的广播会排除发起窗口。
- 已有 2 或更高值不改动，单层团队不修改设置，也不在测试结束时自动降回 1。缺少接口、权限拒绝、格式变化或读回不满足时阻止启动，不预留或创建成员。
- 远端不改本机设置冒充远端准入；高于 2 的旧层级若深度不足则要求明确的原生设置，自动化不会提升至更深层。
- `ensureTeamDepth` 是限定保存的 teamId／configVersion 的受控面板操作，可为既有团队确认该设置，不创建成员、Run、Task 或重发输入。恢复或重读已有启动回执继续保持只读。
