# Questions, deadline scheduling and member launch — 0.5.52

Team Orchestrator keeps its single right-panel default. In **Members**, an approved controller can **Launch session** for an unconnected local Claude member, or connect an existing session. The new process inherits this project's shared-workspace choice and the configured Node/Orca executables. It verifies its own reserved conversation, reads its official role and waits for an admitted assignment. No permission or controller approval is granted to the worker by launch.

Launches reserve capacity in the database before opening a terminal. At the configured cap they remain queued; a running approved controller retries queued requests on its regular 30-second round. Existing bindings and uncertain starts consume capacity conservatively. Nothing is closed or evicted. A claimed start with a missing native receipt is not repeated automatically. **Check launch** refreshes that reservation; connect an existing verified session when operator recovery is required. This increment launches fresh, unconnected members; it does not replace an existing conversation or introduce automatic close/reopen.

In **Inbox → Questions**, choose a direct head or direct report and ask about team coordination or an active task. Questions have their own thread, independent of the assignment's work thread. The answer window is snapshotted from the team and starts on recipient read. Only the addressed recipient can answer an open question before its deadline. An answer settles the question once and queues immutable reply content. Asking or answering never accepts a task or grants file/tool permission. Decisions that must block a task still use its decision gates.

Every running shared member observes question, pickup and task deadlines on its 30-second round. After a reload or restart it catches up on overdue records; no separate daemon runs while every client is closed. Late answers/outcomes are refused even before an observer catches up. Expiry records a system notice for the head and, for questions, the requester. Notices remain visible in the recipient's Inbox until **Mark notice read** or the typed `acknowledgeNotice` command. Conversation context can also carry these notices. Wake attempts use the replay interval and never count as reads. A worker is never falsely recorded as the author of a timeout report.

Existing schema-5 or schema-6 workspaces require **Update workspace**. This explicit action keeps a complete backup and preserves existing approvals, roles, messages and receipts while installing schema 7. Opening a workspace never updates it silently. Legacy classic team files are not imported. PostgreSQL remains an explicitly configured library alternative; this release adds no hosted-store configuration UI or local/online mirroring.
