# Shared workspace controls

Start with **＋ Create team** in the Team Orchestrator band. Complete Team, Members and Options, then use **Review & permission** to enable shared workspace mode for this project and explicitly allow this conversation to manage teams. **Create team** remains a separate final action. See [panel navigation](panel-navigation.md).

The project preference is saved through the Mod's supported configuration as JSON text containing project choices (`projectWorkspaceModes`). It applies to later conversations using the same project path and client installation. It does not travel to another installation, identify a controller, change other projects' choices or override their existing global default. Windows drive paths are matched without case sensitivity for this preference only; native identity verification remains unchanged. Team data stays in the project's `.team-orchestrator/` directory.

**Settings → Connection** provides this project's **On** and **Off** controls plus **Save Node** and **Save Orca**. Editing an executable changes only its draft until Save. Node 22.13+ is required; Orca's existing executable validation still applies. The legacy global preview option remains a fallback for projects without a saved choice. Create also saves an explicit project choice when that fallback is already On; if saving fails, the draft is kept and no creation is submitted. Turning this project's mode Off does not revoke approvals, delete data or bypass shared-member/file guards. If saved project choices are malformed, the panel shows an error and refuses mode saves and shared API operations until the setting is corrected through normal configuration; it does not reset or overwrite unknown choices.

**Open teams** or **Team workspace** checks the current native conversation and reads access. Authorized discovery loads the workspace automatically. An unapproved empty result never claims the project has no teams. **Check access** is also available for refresh and uncertain permission results. Management approval is separate from role membership, file-write permission and Agent permission. Other approved controllers keep their access; the existing conflict guard serializes writes.

Technical session identifiers and receipts stay behind **Details**. If permission returns an uncertain result, Check access must read back the actual state before another approval action. If creation is uncertain, its exact request and operation ID are kept: use **Check receipt**, then **Retry same operation** only if offered. A confirmed creation with a failed subsequent read opens the workspace and offers Refresh, without submitting another Create.

Creation saves roster/configuration only. Use **Connect session** on a member, choose from verified native sessions, then explicitly **Connect selected session**. Neither selecting an option nor creation launches, binds or messages a session automatically. Heads assign and separately accept outcomes; workers read their role/brief and report evidence. See [the workspace guide](shared-team-workspace.md).

This increment does not migrate classic teams, launch shared workers, deliver assignments automatically, execute a scheduler or automatically enforce task windows. Native proof, scoped tickets, generations, leases and idempotency checks are unchanged. The panel uses the existing schema-5 API and packaged store implementation.
