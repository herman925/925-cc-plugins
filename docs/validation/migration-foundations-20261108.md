The shared library's `migration/` directory contains bounded double-capture and fingerprint validation, hierarchy/role/advisory preview, complete private backup/readback and native command assembly. Explicitly pruned mail remains archival; uncertain sending needs outcome reconciliation. Binary bytes and malformed original documents can be backed up without making a malformed source importable. Unsupported providers, ambiguous heads/names, cycles, redirected paths, oversized sources and different/remote original homes stop or require mapping; nothing is silently dropped, repaired or transferred.

The trusted API adds private `importClassicTeam` and `reconcileClassicImport` methods. A specific native review and a post-review verifier for source, backup and safe native source state are mandatory before an effect. The actor is reverified after that callback. The reviewed target home is checked against the actual actor before target writes. The new team, members, roles/advisory notes and source/backup operation receipt are atomic. On failure, all target configuration rolls back; source and backup remain. Both permissions are forced off, and no binding, launch, task, assignment or delivery is created. The head's imported advisory records require review and fresh task admission. Reconciliation retains the exact operation and never repeats an effect.

Ordinary API/model calls cannot select this operation. The public MCP catalogue excludes it. No new SQL table/engine was introduced; schema-10 native API operations use the existing configuration transaction and immutable receipt contract. Both development repository packages remain **59 matching runtime files**. Capture/backup/command integration files are source-only and not bundled into those runtime snapshots yet, since no client migration endpoint exists.
